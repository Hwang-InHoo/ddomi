# 또미 소유 음식점 데이터

`regions/` — 또미가 **소유**하는 전국 음식점 목록입니다. 공공데이터포털
[소상공인시장진흥공단 상가(상권)정보 API](https://www.data.go.kr/data/15012005/openapi.do)에서
`tools/sangga.py`(gicho-hoesa 저장소)로 상권업종 대분류 **I2 음식**만 뽑아 만듭니다.
카카오·네이버처럼 빌린 데이터가 아니라 **이용허락범위 제한 없음**인 공공데이터이므로
사이트가 직접 소유·배포합니다. 좌표는 원본이 이미 WGS84라 변환하지 않습니다.

## 왜 파일을 쪼갰나

전국 음식업소는 84만 곳이 넘어 한 파일에 담으면 100MB를 훌쩍 넘깁니다. 브라우저가 그걸
한 번에 받아 들면 화면이 멈추므로, **시군구 단위로 쪼개 두고 보고 있는 지역만 불러옵니다.**
화면(또미가 골라줘)이 이미 시·도 → 시·군·구 → 동 순서로 묻기 때문에 구조도 그대로 맞습니다.

```
regions/
├── index.json     전국 목차 — 시도 → 시군구, 개수·중심좌표·범위. 모든 화면이 이것부터 읽는다
└── <시군구코드>.json  그 지역 가게 목록 (예: 26230.json = 부산광역시 부산진구)
```

## index.json

| 필드 | 설명 |
| --- | --- |
| `total` | 전국 합계 |
| `sido[]` | `{code, name, count, sigungu[]}` |
| `sido[].sigungu[]` | `{code, name, count, y, x, bbox}` — `y/x`는 중심좌표, `bbox`는 `[최소위도, 최소경도, 최대위도, 최대경도]` |

## `<시군구코드>.json`

`meta`에 지역 정보(개수·중심좌표·범위·동별 개수)가, `items`에 가게가 들어갑니다.
용량을 줄이려고 키를 짧게 썼고, `data.js`가 화면에서 쓰는 긴 이름으로 풀어 줍니다.

| 저장 키 | 화면 이름 | 설명 |
| --- | --- | --- |
| `id` | `id` | 상가업소번호 — 고유 식별자 |
| `nm` | `name` | 상호명 (지점명이 있으면 붙임) |
| `ct` | `category` | 상권업종 소분류 (예: 카페, 백반/한정식) |
| `ad` | `roadAddr` | 도로명주소에서 `meta.prefix`(시도+시군구)를 뺀 나머지 |
| `dn` | `dong` | 행정동 |
| `y` / `x` | `lat` / `lng` | 위도 / 경도 (WGS84) |

## 점수는 넣지 않습니다

또미 신뢰점수는 이 파일에 없습니다 — 실제 미식가 평가가 쌓이기 전까지 모든 가게는
**"평가 준비중"**으로 표시됩니다(가짜 점수 금지 원칙).

## 갱신

원본이 분기마다 갱신됩니다. 다시 받으려면 gicho-hoesa 저장소에서:

```
python tools/sangga.py --collect --out <작업폴더>
python tools/sangga.py --build   --out <작업폴더>
```

그런 다음 `<작업폴더>/regions/`를 이 폴더로 덮어씁니다. API가 빠른 연속 호출을 429로 막으므로
수집은 30분 안팎 걸리고, 중간에 끊겨도 같은 명령으로 이어서 받습니다.
